### Verdict: CLEARED-AFTER-FIXES

`IsGone` is sound. It returns true only when a PID has no process, or its process has exited, so it cannot pass a
process that can still read console input. The remaining problem is not in the code: the stale entry stays on the
console for the rest of its life, and the steps run after it is created.

### MUST-FIX

1. **A stale entry lasts as long as the console, so a reused PID gives a false REFUSED or HARD STOP. Run 6b last
   and pin `consoleStale`.**
   - Evidence, dry-pass ledger: stale PID 75304 from s6b is still on the console in s7-control, s7-control-judge
     and s8c (`console=[75304;63364]`). In `f3test`, 69984 is still there two calls later.
   - Once any process on the host reuses that PID, `IsGone` correctly reports it as live. Every later call is then
     REFUSED at start. If the reuse happens during a call, that call ends with `consoleForeign=1`, which is a
     **HARD STOP** that the rehearsal records as FAIL.
   - A busy capture host recycles PIDs quickly. This is fail-closed, but it is likely enough to cost the attended
     slot, and it would put a false containment failure on the record.
   - Starting calls despite stale entries also loosens M3. A stale entry proves this console sent a Ctrl+Break
     somewhere, and F3 now accepts it without asking who sent it.
   - Fix, operator text only (no hash change):
     - In the spec and in packet section 4, run 6b as the **last** `c3_run.ps1` call, after step 8 and before
       step 9.
     - Add this rule: "`consoleStale` must be `[]` on every ledger line except s6b. On s6b it may only be
       `[close:<one PID>]`. Any other value → ABORT (unexplained stale entry, or a console that was not fresh)."
     - This removes the PID-reuse exposure for every later step and puts back the freshness guarantee M3 had.

### SHOULD

- **S-F3a. Set the 6b pin from step 4 and remove the contradiction.**
  - The spec says a non-reproducible 6b "is not an abort" but gives `startedPin=DIFF`. Three lines later it says
    "Abort if `verify` is not `OK` (this includes `startedPin=DIFF`)".
  - Fix: `$pin6b = if (<step 4 printed patched: true>) { 2*$k+2 } else { 2*$k+1 }`, and pass `-ExpectStarted $pin6b`.
    Then both branches give `verify OK`, and the abort rule holds without exceptions.
  - The same pin also covers a host whose conhost placement differs: a DIFF there stays an abort, which is correct,
    because it is unexplained.
- **S-F3b (optional; changes the hash).** Bind each stale exclusion to a cause this rehearsal produced:
  - at close, exclude a gone PID only if it is in `$seen`;
  - at start, exclude it only if a previous ledger line has it as `close:<pid>`.
  - MUST-FIX 1 makes this unnecessary for the launch.

    state cannot receive console input.
  - Protected processes can be opened with these rights, so they show as live.
  - Access denied, any other open error and `WAIT_FAILED` all count as live (fail closed).
  - A reused PID shows as live (fail closed; that is MUST-FIX 1).
