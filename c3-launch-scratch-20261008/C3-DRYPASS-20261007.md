## F3: the 6b HARD STOP (first run) and its fix

First run (`run1\`):
- s6b gave `started=6` against the pin `2k+1=5`, and `consoleForeign=1`, so `verify=HARDSTOP`;
- the next call (`s7-control`) was `REFUSED`, because the console was shared with the stub's PID.

Diagnosis (`diag1\`, `phantom\`):
- (a) The 6b mutant's `CREATE_NO_WINDOW` gives the stub its own `conhost.exe`. It is created inside the Job, so 6b is
  structurally **`2k+2`**.
- (b) The runner (`_default_launcher_runner`, lines 361-391) creates the stub with `CREATE_NEW_PROCESS_GROUP` and sends
  `CTRL_BREAK_EVENT` to it from the C3 console. The stub lives on its own console. conhost then adds the stub's PID to
  **this** console's `GetConsoleProcessList`, and the entry stays after the process exits.
  - Reproduced in isolation, outside C3: the entry appears only when the Ctrl+Break is sent; the control without it
    leaves nothing.
  - The PID has no process. Nothing escaped (`escaped=0`, `stillAlive=0`). The PIDs from both runs were checked
    afterwards and were not alive.
  - So this is a stale list entry, not containment harm. But v3.1 counted it as foreign, and refused every later call
    in that console.

Fix, `c3_run.ps1` version `c3-run-v3.1-F3`:
- `Native.IsGone(pid)`: `OpenProcess(SYNCHRONIZE|QUERY_LIMITED_INFORMATION)`. A PID counts as gone only on
  `ERROR_INVALID_PARAMETER` (no such PID), or when the process object is signalled. Every other failure counts as live
  (fail closed).
- Gone entries are recorded in the new record-only field `consoleStale`, and excluded from both the start refusal and
  `consoleForeign`.
- `consoleForeign>0` stays a HARD STOP (Q5).
- 6b is re-pinned to `2k+2`.

Isolated test (`f3test\`), in a fresh console:
- a clean call gives `consoleStale=[]`, OK;
- with a stale entry present, the call gives `consoleStale=[pid;close:pid]`, `consoleForeign=0`, OK;
- with a **live** foreign process on the console, the call is still `REFUSED`.

## F4: step-7 judge folder (operator text only)

`$w = @(Get-ChildItem …).FullName` returns a **string** when there is exactly one folder. So `$w[0]` is `C`, and the
judge refuses. It fails closed, but step 7 could never pass. Both step-7 lines (7.0 and 7.1) now use
`@(Get-ChildItem … | ForEach-Object { $_.FullName })`. No script hash changed.
