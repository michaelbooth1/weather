## Design (H1-H7)

- **H1 gate.** `v3_gate.Gate` decides each request by (family, date, purpose) and fails closed when
  a source is missing or malformed. It has no hard-coded date.
  - It reads the whole status paragraph of
    [reserved-confirmation-window.md](../operations/reserved-confirmation-window.md). Dated
    `MG-1 D0 = … / MG-1 last = …` reserve exactly that range. Undated `RESERVED … D0 >= X` reserves
    from X, open-ended. Both apply only to arms with `READS_NBM_GUIDANCE`.
  - It also reads the forward alpha ledger, schema `forward_alpha_ledger/1`. Each row has:
    - `row_id`, `family` (`*` = all);
    - `date_start`, `date_end`;
    - `status`: `reserved`, `closed_by_default`, `open` or `spent`;
    - `scope`: `join` or `all`;
    - optional `alpha`;
    - `decided_by`, `decided_at`, `reason`, `source`.
  - Rules:
    - `reserved` always wins, and `scope: all` also refuses outcome-free coverage.
    - `closed_by_default` refuses joins unless an `open` row names the requesting family.
    - `open` serves only `confirmation`; a development read of an opened date is refused because it
      would spend the date.
    - `spent` refuses `confirmation`.
  - The four committed rows:
    - 2026-10-16..11-13 reserved, all scope;
    - ≥ 2026-09-30 closed by default;
    - 07-31..09-29 spent;
    - 06-03..07-30 spent.
  - No row is open, so every label or market join on or after 2026-09-30 is refused.
- **H2 dry run.** `v3_dryrun` imports only `v3_gate`, `v3_inputs` and `v3_arms`. It opens only
  `manifest.json` and the two input parquet files, through one sha-checked `open` each. Before
  opening, it gates every date the manifest lists for the file.
  - A test plants the label and market files next to the inputs. It then runs the dry run in a
    subprocess with a `sys.addaudithook` and asserts the planted files are never opened and that
    `v3_outcomes`/`v3_score`/`harness` are never imported.
  - An AST test enforces the same import rule.
- **H3 power.** `v3_power` takes variance components (date, market, residual) from a development
  stats entry. It uses the crossed, date-only and market-only bootstrap SEs, with residual
  r = max(0, s_d² + s_m² − s_c²). It simulates crossed tables at `--effect-fraction` (default ½)
  of the dev estimate and reports P(GO | effect), P(GO | null) and analytic MDE80. It returns
  `UNTESTABLE` when MDE80 > `--bar`.
- **H4 single-shot.** `v3_score.run` / `python -m tools.research.model_parity.v3_score` runs in
  this order:
  1. Exits 3 if a sealed result for the prereg already exists.
  2. Verifies the prereg sha256 and each arm's pinned code sha256 (exit 2 on mismatch).
  3. Gates every (family, date) (exit 5).
  4. Builds the arms and their input-removed twins from inputs only.
  5. Seals the futility boundaries.
  6. Joins labels and market prices and screens the inputs for planted labels, by name and by
     content (exit 4).
  7. Scores every arm in one pass.
  8. Seals the result: JSON, a `.sha256` sidecar, and the read-only attribute.
  9. Writes the ledgers, and only then prints.
- **H5 endpoints.** E1 is R = Brier_arm / Brier_market per block (equal market-day ratio of
  means, W-based interval). E2 is a blend w·arm + (1 − w)·market, with w frozen in the prereg and
  fit only on dates ≤ 2026-09-29 (`fit_blend_weights` refuses later dates). It is labelled
  "complementary information (model+market blend), NOT edge".
- **H6 label ledger.** `v3_outcomes.LabelLedger` writes one row per (family, date, market). Each
  row holds the settled bucket, `promotion_countable` (always false for development), the prereg
  sha and the write time. It holds no forecast, price or score. A re-record is skipped, and a
  conflicting label raises an error.
- **H7 futility.** Non-binding Lan-DeMets O'Brien-Fleming-type β-spending. For looks [0.5, 1.0] at
  α = 0.025 one-sided and β = 0.2, the interim futility boundary is z = 0.509 (β spent 0.0699) and
  the final boundary is z = 1.960. The boundaries are sealed before the join; a test spies the
  join to prove the order.

## Caveats

- The (b) design sits at the 4-date minimum, so the mid-power regime (about 60%) is still
  untested. The structured injection carries less variance than real candidates do, and z-based
  crossed intervals with 4 dates are anti-conservative. Before a prereg relies on H3 near 50-70%
  power, re-run (b) with noisier injection.
- The residual variance component comes out as 0 in both the injected control and MG-1's
  components: the W crossed SD exceeds date-only ⊕ market-only. H3 is therefore approximate.
- (a) reproduces from a committed fixture, not by re-scoring tapes. The fixture's own dates are
  outside the dev window.
