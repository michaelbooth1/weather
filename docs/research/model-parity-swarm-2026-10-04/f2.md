# F2 venue-rule labels: report (development only)

**Status: COMPLETE.** The venue rule is reproduced exactly. On all 626 market-days, the label "daily max over routine + SPECI METARs (COR versions kept) on the local clock date, with each observation's T-group tenths of a degree C converted to F and rounded half up" equals the extract's `settlement_high` and lands in the extract's winner band (**0/626 band disagreements, 0/626 value disagreements**). Use the label `RS_ct`.

The 1-minute ASOS true max is **not** the settlement quantity. On the 230 days with full 1-minute coverage, it lands in a different band from the winner on **156 (67.8%)** of them. It sits above the hourly-row label by +1.47 F on average (+1 F on 112 days, +2 F on 88).

All numbers here are development numbers. F2 is a label agent and did not use the harness: nothing was scored and no rule was registered, so these results add nothing to the multiplicity count. `winner` and `settlement_high` were read only to measure disagreement.

## Consequences for hunters
- Settlement mechanics (T16): this table's settled value is the hourly-row-plus-SPECI METAR max, not the true continuous max. A candidate that targets the true max is biased by about +1.5 F and would pick the wrong band on about two-thirds of days. The hourly-row versus true-max gap is real, and it is a gap between the physical maximum and the settled value.
- Running max and decided-band rules (T1, T2, T4, T13): compute the at-t running max as `RS_ct` restricted to valid time <= t - 10 min. This is the same quantity that settles. SPECIs matter: dropping them changes the label on 15 days and the band on 9 (1.44%). They only ever lower it. Dropping COR reports changes the band on 6 days, 4 of them at Miami, so the corrected report is the one that settles. Rule 1 still excludes COR from candidate inputs. Any lost information from that exclusion is small, but a hunter that uses a running max should say so.
- Hunters other than settlement-mechanics hunters can keep scoring on `winner`. F2's rate to place beside it is **0.00% band disagreement** for `RS_ct`, so `winner` and the venue label are the same object on this table.

## Definitions (rounding rules stated)
- Source: `C:\swarm\data\iem\metar\<ICAO>.parquet` (A-IEM-1, IEM asos.py, report_type 3 = routine and 4 = SPECI). Local dates are restricted to <= 2026-09-29. The acquirer truncated the files at the end of local 09-29, so 0 rows are on or after 09-30.
- Variants: **R** = routine (hourly) only. **RS** = routine + SPECI. **RSnc** = RS without COR reports.
- Duplicate rows at the same (valid_utc, report_type) keep the augmented row in preference to the `MADISHF` raw-ASOS twin. One row was dropped (KDAL).
- Conversions are applied per observation, then the daily max is taken. Rounding is monotone, so the order does not matter.
  - `cw` (whole-degree C): F = round_half_up(C_body x 9/5 + 32). C x 18 is always even, so there are no .5 ties.
  - `ct` (T-group tenths): computed exactly in integer hundredths of a degree F, F100 = tenths x 18 + 3200, then F = floor((F100 + 50) / 100), which is round half up. Ties at exactly .5 F occur only when tenths = 25 mod 50, that is at x2.5 and x7.5 C. All 38 tie rows are at KBKF. A missing T-group falls back to `cw` for that observation (302 rows over all stations, 158 of them at KBKF).
  - `ct_even`: the same with round half to even, as a sensitivity check. It disagrees once: denver 2026-09-15, T-group max 72.5 F. Half up gives 73, which matches settlement. Half even gives 72. This is direct evidence for half up.
  - `im`: round_half_up(IEM `tmpf`), a diagnostic of the IEM-served value. KBKF 92.48 F is served as 93, which gives 3 value misses.
- Day: the primary definition is the local clock date. The diagnostic is the local standard-time day (the NWS climate convention). It disagrees with the winner once, and the winner agrees with clock time. The LST day for 09-29 lacks the 00 h on clock 09-30 by construction (rule 5).
- 1-minute truth: `C:\swarm\data\iem\onemin\<ICAO>.parquet` (A-IEM-4) gives the max of 1-minute `tmpf` (whole F) per local date. It is truth or label use only and NOT point in time (rule 1). "Full" means coverage_frac >= 0.9 and >= 456 of 480 minutes in 10-18 local. KBKF has no 1-minute archive at IEM, so Denver has no truth. Coverage is partial elsewhere (230 full days, 517 with any data).

## Caveats
- `settlement_source` is `daily_summary` for every row. If production derived `settlement_high` from the same METAR stream, the value match is partly by construction. The **winner band** comes from the venue ledger (`ledger_authority`), and it also matches 626/626, so the venue rule result does not depend on that.
- Bands are 2 F wide, so every integer is on a band edge. An "at band edge" lens is therefore trivial on this table. Use the distance from the unrounded T-group max (`RS_ct_raw_max`) to the .5 rounding boundary instead.
- The 1-minute values are 1-minute averages in whole F, with gaps. The true-max excess (+1.47 F) covers 10 markets and full-coverage days only (230 of 572 possible).
