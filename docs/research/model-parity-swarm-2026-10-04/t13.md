## Rules registered before the first score (C:\swarm\registry.jsonl, 01:00:47 local; 5 entries)

**Shared state at snapshot t.** One `state()` function serves both the history grid and the live snapshots.
- Market station: non-COR METAR/SPECI rows from a-iem-1, with available = valid + 10 min <= t and local date =
  target date. These give the running max M (rounded tmpf), the current temperature T, and the deficit bin
  {<=0, 1-2, 3-5, 6+}.
- Neighbour k: the closest <= 6 ASOS/AWOS stations within 50 km (a-iem-3; 5-6 per market). Non-COR rows, with
  available = valid + 10 min <= t and local date (in the market's time zone) = target date. These give the
  neighbour running max N_k, and the latest temperature C_k if it is <= 90 min old.
- Anomalies: A = median_k(N_k) - M and Ac = median_k(C_k) - T, each requiring >= 2 neighbours.
- Bins: terciles of A (or Ac) per station x local hour, pooled over hours h-1..h+1, fitted on history only.

**History.**
- Local dates 2026-05-01..2026-07-31 only (the neighbour archive starts 05-01), on a quarter-hour grid, giving
  91-92 days per station.
- F = the market station's maximum rounded tmpf over the local date, requiring >= 18 rows. R = F - M, clipped to
  [0, 40].
- A cell is station x hour window x deficit bin [x tercile] and needs >= 25 distinct days. Otherwise there is no
  candidate and the served fallback applies.

| id | rule |
|---|---|
| t13-r1 | p_served x [band mass P(R / st,hour,db,A-tercile) / band mass P(R / st,hour,db)], renormalised |
| t13-r2 | standalone band mass of P(R / st,hour,db,A-tercile), shifted by M |
| t13-r3 | as r1 but conditioned on the Ac (current-temperature) tercile |
| t13-c1 | CONTROL: P(R / st,hour,db) on the r2 rows, with no neighbour term |
| t13-r1s60 | SENSITIVITY: r1 with every METAR availability set to valid + 60 min, in history and live |

(In the table, "/" stands for "given".) Nothing was tuned on the evaluation table. The tercile edges and the cell
distributions come from May-Jul 2026 IEM METAR only.

## Point-in-time statement

- **Availability rule.** A METAR/SPECI value enters at snapshot t only if valid + 10 min <= captured_at_utc. This
  is the manifest basis and the DESIGN rule 1 minimum. COR reports are excluded, and no 1-minute or 5-minute data
  is used.
- **Checks in code.** The code asserts that the latest availability used (the maximum over the market station and
  every neighbour) is <= t for every covered snapshot. It also runs `h.assert_point_in_time` on 3,000 sampled
  snapshots.
- **Caveat.** IEM keeps no per-report receipt time, so valid + 10 min is an assumption. This matters most for AWOS
  neighbours (`is_awos` in selection.json), which may reach public feeds later. The +60 min sensitivity leaves the
  verdict unchanged, because r1 is NULL either way.
- **No market input:** the code reads only `h.candidate_inputs()` and the IEM files.
- **No settlement leakage:** the code reads no winner or settlement column, and the history label F uses dates
  <= 07-31 only.
- **Floor:** applied by the harness.
- **Dates:** neighbour valid_utc < 2026-09-30 is asserted.
- **Hour gate:** none.

## Serveability

**Class: needs new capture.**
- **What production would add:** real-time neighbour ASOS/AWOS METAR capture.
  - 63 stations, about 5-6 per market.
  - Hourly reports plus SPECI, from a free public feed (aviationweather.gov / IEM).
  - About one request per market per poll cycle, a few MB a day.
- **The serving stage itself:** zero-parameter, built from history lookups.
- **This capture is not justified** at the measured effect sizes: about -0.0005 at best, and indistinguishable
  from 0.
- The remaining-rise family that drives the LEAD numbers above (T2/T1) needs only the market-station running max,
  which production already captures.

## Interpretation and caveats

- **Why the history signal does not score.** The neighbour signal is real in history. Either served already
  reflects it, or the station x hour x deficit remaining-rise climatology subsumes it. Adding it as a condition
  does not move Brier on this table.
- **17-23.** The decided band after the peak dominates, and neighbours carry no extra information there.
- **06-09 harm (r3).** The morning anomaly tracks the overnight carry-over, not the rise still to come.
- **Short history.** History covers only 92 days at the edge of the season (May-Jul).
  - The station x hour terciles absorb static siting offsets, such as coastal versus inland stations.
  - A 2024-2025 neighbour archive would allow finer cells. In 17-23 the r2 - c1 intervals are already tight
    around 0.
- **Multiplicity:** 5 registry entries (r1, r2, r3, c1, r1s60). c1 is a control and r1s60 a sensitivity.
