## Rules registered (C:\swarm\registry.jsonl; 4 entries, multiplicity count 4)

Common to all variants:
- **History:** IEM METAR/SPECI from the a-iem-1 manifest, local dates **<= 2026-07-31**, non-COR rows
  that have tmpf (routine and SPECI).
- **Day final max:** F = max(round(tmpf)) over the local date. History days need >= 18 rows.
- **State at time t** (one function, shared by the history grid and the live snapshots):
  - Rows on the target local date with available = valid + 10 min <= t.
  - Running max M, and current temperature T from the latest row.
  - Deficit d = M - T, binned {0, 1-2, 3-5, 6+}.
  - 2 h slope s = T minus the temperature at the latest row valid <= latest - 110 min (within 4 h),
    binned {<= -2, -1..+1, >= +2, unknown}.
- **History grid:** every local day, at local hh:00/15/30/45. Target month m uses history months
  m-1..m+1, so Aug uses Jul-Sep and Sep uses Aug-Oct, from 2024-07 to 2026-07.
- **Cell:** (station, target month, local hour, d, s). Each cell holds the empirical P(R = F - M).
  A cell with fewer than 40 distinct days backs off to drop s, then drops d.
- **Mapping and fallback:** P(final = M + r) is mapped to integer-degF bands. The harness applies the
  rule-4 floor. A snapshot with no target-date METAR yet gets the served fallback.

The variants:
- **t2-r1:** nowcast alone.
- **t2-r2:** p_served x p_nowcast, renormalised.
- **t2-r3:** served, with bands entirely above M + q99.5(R) zeroed.
- **t2-r1s60:** r1 with METAR availability = valid + 60 min in both history and live. This is a
  PIT stress sensitivity, not a new rule.

## PIT statement

- The only external input is METAR/SPECI from IEM asos.py. A row enters a snapshot only if
  available_utc (valid + 10 min, the manifest basis) <= captured_at_utc and is_cor is False.
  - The code asserts av <= captured for every covered snapshot.
  - `h.assert_point_in_time` is called on a 2,000-snapshot sample of the latest rows used.
- The +60 min stress (t2-r1s60) keeps both LEADs (table below).
- Fitted content is the empirical R tables only, built from local dates <= 2026-07-31 (asserted).
- **No market input.** Inputs come from `h.candidate_inputs()` (allow-listed) plus METAR. No
  winner/settlement field is used.
- **No 1-minute data.** IEM 1-minute data is not used anywhere.
- **No hour gate.** No hour gate is chosen. All variants run at all hours, as registered (rule 8).
- **Caveat:** IEM keeps one row per valid time, so a COR can replace the original. Excluding COR
  then leaves a missing hour, which is conservative.

## Interpretation

- **00-16 vs 17-23.** In 17-23 a station-month-hour climatology of the remaining rise, conditioned
  on the at-t METAR deficit and slope, removes about 95% of the served excess. This is the T1
  "decided band" effect, recovered with no hand-picked thresholds.
- **13-16.** It removes about 55% of the gap.
- **00-12.** The pure climatology is statistically tied with served: point estimates are slightly
  better, and markets are split about 4-7 of 11. It neither helps nor harms there.
- **Tail.** From-stratum share of tail excess removed:
  - 17-23: 0.95;
  - 13-16: 0.74;
  - all hours: 0.66.

Caveats for refuters:
1. METAR availability at +10 min is the manifest basis. The +60 min stress is reported above.
2. The day max in history is the METAR hourly-row maximum. WU settlement can differ (F2 venue-label
   rate). The live scoring uses `winner` through the harness.
3. Aug/Sep 2026 targets use 2024-2025 plus Jul 2026 history only.

## Serveability

**Class: needs retrain.** This is a new fitted lookup stage, so it needs a model/release change and
is not serveable this season.
- **The table:** a static artifact with about 11 stations x 2 months x 24 hours x 16 cells of
  41-bin vectors. It is fitted on history <= 07-31 and would need refitting per season/month.
- **The inputs** are free public METAR:
  - running max (production already captures `high_so_far` / `trusted_current_max`);
  - latest temperature;
  - temperature about 2 h earlier.
- **New capture needed:** the latest METAR temperature and the 2 h-earlier temperature (or slope),
  at snapshot cadence. Production snapshots currently carry no current-temperature feature. The
  data is free, adds a few bytes per snapshot, and has no new external dependency if the existing
  METAR poll is reused.
- **Train/serve parity:** the same state function must run at serve time with the same
  availability rule (valid + 10 min, COR excluded).
