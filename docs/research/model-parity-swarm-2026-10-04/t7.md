## Rules (registered before the first score; C:\swarm\registry.jsonl, agent t7)

- Rules t7-r1..r5 were registered at 00:55:18 local. The controls t7-c1 and t7-c2 were registered at
  01:02:51, after r1-r5 were scored and before the controls were scored. That gives 7 registry lines.
- **Shared construction.**
  - Source: IEM MOS archive. MAV is IEM `GFS`, MET is `NAM`, and MEX, LAV and NBE keep their names.
  - Availability per run:
    - NBE: S3 LastModified (measured).
    - MAV: runtime + 4h30 (NCO production-status evidence).
    - MET: + 4h00, MEX: + 5h00, LAV: + 1h00. These are manifest assumptions, not measured.
  - For each model, use the latest run with available_utc <= captured_at_utc that carries the needed value.
  - Day-max value: MAV/MET/MEX n_x or NBE txn at ftime (D+1) 00Z. For LAV, the maximum hourly tmp over the
    local day, used only if the run covers local 10:00-18:00.
  - Gaussian with integer rounding: P(lo-0.5 <= Y < hi+0.5).
  - Bias b_h and spread s_h = max(sd, 0.5 F) per local hour h, pooled across the 11 stations. They are
    **fitted only on local dates 2026-06-01..07-31**, at synthetic h:30 snapshots, against IEM METAR truth:
    rounded tmpf, routine + SPECI, non-COR, station local day.
  - The harness floor is applied. Any uncovered row gets served fallback.
- **r1:** Y ~ N(mean of the 5 day-max values + b_h, s_h).
- **r2:** for each model, R_m(t) = the maximum of that run's values valid in (t, next local midnight].
  - tmp values count at their ftime.
  - n_x/txn counts as valid at local 15:00, a fixed a-priori choice.
  - Y ~ N(mean R_m + b_h, s_h), and X = max(floor, Y): the lowest floor-possible band receives P(Y < its
    upper edge).
- **r3:** r2 with +2 h on every unmeasured lag (MAV, MET, MEX, LAV), applied in both the fit and scoring.
- **r4:** r2 using NBE alone.
- **r5:** 0.5*served + 0.5*r2, with the weight fixed a priori.
- **c1 / c2 (controls):** r1's construction and parameters, centred on captured v2_mean (with v2_available_at
  <= t) or on captured nws_grid_high.

## Point-in-time statement

- **Availability check.** Every MOS run used for a snapshot has available_utc <= captured_at_utc.
  - This is asserted for every covered snapshot with `h.assert_point_in_time`, on the latest availability
    among the runs used.
  - For c1 it is also asserted on v2_available_at.
- **Measured vs. assumed availability.**
  - Only NBE availability is a measured per-object timestamp (S3 LastModified).
  - MAV has NCO schedule evidence.
  - The MET, MEX and LAV lags are documented assumptions with conservative margins. IEM keeps no
    per-bulletin timestamp for them (manifest note).
  - Under a strict reading of rule 1, only r4 is clean. r4 is LEAD in every block. r3 (+2 h) shows the
    result does not depend on the assumed lags.
- **No leakage paths.**
  - No market input, and no winner or settlement value in any candidate.
  - METAR truth is used only to fit b_h/s_h on dates <= 07-31.
  - No hour gate is chosen on this table (rule 8). The 15:00 valid time for n_x and the LAV 10-18 coverage
    test are a-priori definitions.
- **Caveat for the PIT refuter.** NBE/NBS LastModified values are as early as about 36-40 min after runtime
  (manifest quantiles). That is earlier than typical NBM text dissemination. Please re-derive.

## Serveability

- **t7-r1 and t7-r2: needs new capture.**
  - What to capture: MOS text for MAV (4x/day), MET (2x/day), MEX (2x/day) and LAV (hourly), plus NBE
    (hourly, from S3 blend text).
  - Sources: free NOAA/NWS (tgftp or NOMADS MOS bulletins, or the IEM MOS API) and the NBM S3 text, with no
    key. That is a few KB per station per run, about 30 objects a day plus the hourly NBE/LAV.
  - Parameters: 48 b_h/s_h values fitted on history. At serve time it is a zero-refit stage that replaces
    the served distribution, combined with the 81a floor (max(floor, Y) for r2).
  - Parity work: availability timestamps must be captured per object at fetch time.
- **The cheaper route suggested by c1 is a control, not a candidate.** A Gaussian centred on already
  captured NBM v2_mean, with a history spread, would be a zero-new-capture serving stage. It needs its own
  pre-registration, and it touches the closed "recalibration" thread. The synthesis and owner should decide
  whether it is in scope; T7 did not register it as a rule.
