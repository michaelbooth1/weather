## Independence and what this does and does not show
- Independent: the code. I built it only from the registry text (t10 ids, C:\swarm\registry.jsonl
  lines 73-78), the harness API, and the A-ECMWF and A-IEM-1 manifests and schemas. I did not open
  t10_ecmwf_ifs.py.
- Not independent:
  - I read T10's report before coding, as the task allowed. It shows T10's fitted (b, s) values, which I used
    only as an after-the-fact check. My fits came out identical.
  - Both implementations share the harness, the A-ECMWF values.parquet (bilinear 2t/mx2t3 and the measured
    LastModified PIT basis) and the A-IEM-1 METAR parquet. Upstream extraction or PIT errors in those inputs
    would therefore be common-mode, and this re-implementation cannot detect them (that is refute-pit-t10's job).
- Interpretation choices that the rule text leaves open. Both codes made the same choice each time,
  since the result is bit-exact:
  - E = local clock midnight ending D (zoneinfo, DST-aware).
  - Run availability = max per-row available_utc_measured over the station-run (both params, all steps).
  - "Latest eligible run" = max run_utc among eligible runs.
  - "Carries valid times up to E" = last 2t/mx2t3 valid time >= E.
  - Usable mx2t3 only. The step-0 placeholder is excluded.
  - Window "inside [t, E]" means start >= t and end <= E.
  - "Rounded tmpf" = floor(tmpf + 0.5).
  - Routine non-COR METAR rows with non-null tmpf. Running max uses available = valid + 10 min <= t.
  - H = max(B, X) with B = floor(F + 0.5) and X discretised on integer bins (k +/- 0.5). lte, eq and gte bands
    are taken from the CDF of H.
  - c2 sigma = max(v2_stddev, 1). c2 uses only rows where v2_available_at <= captured_at and r2 covers the row.
  - d1 availability = station-run max of available_utc_conservative, and LM + 60 min, with r2's (b, s) frozen.
