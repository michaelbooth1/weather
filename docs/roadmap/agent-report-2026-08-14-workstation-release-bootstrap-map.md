### Activation is promotion; there is no separate activation command

The only command that writes an active pointer is
`release_lifecycle_cli promote`. For a research-only first identity it requires
`--bootstrap-first-release`, changes the release kind to
`serving_identity_bootstrap`, and returns `restart_required=true`. The code
calls the result `PROMOTED`; there is no weaker “activate but do not promote”
operation.

This is a special **release-lifecycle promotion**, not production model
qualification. The pointer remains `production_capable=false`; capital-canary
and live-pilot authority remain blocked. It is nevertheless a real pointer
transition and requires the full reviewed decision and fresh boundary proof.

## P1 — decision list

### D1. How to break the empty-store source cycle

**Assertion/authorization:** choose one reviewed way to provide the immutable
source required by `--model-source-release`, or authorize a code change that
removes the cycle without weakening lineage.

**If wrong:** a synthetic, stale, or unrelated source silently becomes the
pooled-model and training/evaluation lineage authority for the research parent.
Every later base child inherits that false provenance.

**Commitment:** selecting an external source commits the parent to that exact
release, manifest, pooled-model hash, corpus-role hash, and lineage. The
production host has no such source today. The retained workstation synthetic
release is proof material only.

This is the blocking decision. Safe code-level options include a reviewed
first-parent builder that can prove current tracked corpus lineage, or separate
base-parent store/pointer parameters so a research store can be used while the
production bootstrap store remains empty. This branch implements neither.

### D2. Freeze the all-shadow parent contents

**Assertion/authorization:** approve the parent ID, exact source release,
current tracked family-secondary manifest and artifact registry, exact runtime
fleet, seven base components per market, and 12-market all-shadow route.

**If wrong:** immutable parent contents cannot be corrected in place; the
retrain copies unchanged roles and estimator parameters from the wrong parent.

**Commitment:** an immutable research release is created. It is all shadow and
inactive, but it permanently freezes the current base graph and supplied
model/corpus lineage inside that scratch store.

### D3. Assert the promotion-decision JSON

**Assertion/authorization:** exact verified release ID and canonical manifest
self-hash; `decision=PROMOTE`; `gate_status=PASS`;
`candidate_only_build=true`; `release_kind=serving_identity_bootstrap`;
`reviewed=true`; nonblank human reviewer; timezone-aware review time.

**If wrong:** an unreviewed or misbound research identity becomes the active
parent. The validator checks the asserted values; it does not independently
derive human review or `candidate_only_build`.

**Commitment:** the decision object hash and reviewer/time are embedded in
pointer sequence 1. This is a promotion action even though it grants no
production capability or capital permission.

### D4. Assert the fresh market-day-boundary JSON

**Assertion/authorization:** same exact release/manifest; effective target
date; `at_market_day_boundary=true`; all release-writing processes quiesced;
empty open- and mixed-release day lists; timezone-aware `observed_at_utc`
written last and no more than 900 seconds old.

**If wrong:** pointer transition can split a market day or mix release identity
in downstream evidence. The validator checks the claims and freshness; it does
not discover open writers or market days.

**Commitment:** the boundary proof hash, effective date, and observation time
are embedded in the pointer. A stale proof requires a new human observation,
not a timestamp edit detached from the checks.

### D5. Authorize `--bootstrap-first-release`

**Assertion/authorization:** explicitly permit the one-time research-only
serving-identity promotion while no pointer exists.

**If wrong:** the active parent may be trusted as an operational production
release when it is only a research identity.

**Commitment:** pointer sequence 1, `serving_identity_bootstrap` origin
provenance, and `restart_required=true`. Rollback can return to no pointer, but
requires another reviewed boundary and does not erase the release or history.

### D6. Bind the base-retrain plan

**Assertion/authorization:** target date, training-as-of, exact parent ID,
parent feature-contract hash, official base corpus manifest, immutable PIT
manifest, new candidate directory, and reviewed runtime ID.

**If wrong:** the fail-closed gates should block, but any incorrect evidence
that nevertheless passes would bind the wrong population or parent into all 12
fits. Candidate output is exclusive and not repaired in place.

**Commitment:** a successful fit freezes a research-only child release and
copies all non-replaced parent roles at exact hashes. This is the first act in
this sequence that creates a retrained candidate.

### D7. Declare the confirmation window at candidate freeze

**Assertion/authorization:** once the first retrain candidate is fitted and
frozen, immediately date and size the forward reservation against endpoints
that still stand, before any confirmation scoring.

**If wrong:** confirmation dates can be consumed or selected after seeing
results, permanently destroying the holdout.

**Commitment:** future dates become unavailable to research/MM scoring under
the rules in `reserved-confirmation-window.md`. Nothing is reserved before
that fit/freeze event.

freeze the retrained candidate, not the June HGBs. The bootstrap parent is
