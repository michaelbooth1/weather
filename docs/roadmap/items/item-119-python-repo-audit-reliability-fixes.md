# 119. Python Repo Audit Reliability Fixes [COMPLETE 2026-06-18 - AUDIT FIXES LIVE]

Goal: close concrete issues found during the 2026-06-18 folder-by-folder Python
audit without creating broad refactor churn.

Source: 2026-06-18 full Python audit. Mechanical checks found one failing test,
a repo-root import parity gap, a long-job cleanup exception-suppression risk,
retired research scripts that could still run stale live probes, drift in
legacy wrapper behavior, stale unused locals in model/market/source code, and
unregistered production schema literals in source modules. Final verification
also exposed a runtime-identity fingerprint bug where generated bytecode under
`tools/__pycache__` could be treated as source and trip the stale-code guard.

## Design

1. Keep the canonical package under `src/weather`, but make repo-root Python
   subprocesses import `weather.*` the same way editable installs do.
2. Preserve legacy `src/*.py` compatibility wrappers while requiring every
   wrapper to forward both imports and `python -m src.<module>` execution to
   the canonical `weather.*` module.
3. Retire stale live research scripts as explicit `--help` stubs, so no
   retired probe can make network calls, mutate files, or launch training by
   accident.
4. Make long-job guard cleanup exception-safe: lock and environment cleanup may
   run, but it must never suppress the original job exception.
5. Remove stale unused locals only where they were proven to be dead assignments
   rather than compatibility re-exports.
6. Keep source-code schema literals registered so strict registry audits can
   distinguish production artifacts from intentional unknown-schema test
   fixtures.
7. Keep runtime source identity stable across normal Python cache generation by
   fingerprinting real source files while excluding `__pycache__` and compiled
   bytecode.
