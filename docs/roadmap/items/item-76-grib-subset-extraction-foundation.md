# 76. GRIB Subset Extraction Foundation [COMPLETE 2026-06-16 - GRIB CACHE POLICY LIVE]

Goal: create a small, reusable extraction path for free GRIB2 sources before
individual source integrations duplicate brittle download and parsing logic.

Source audit: `docs/research/FREE_WEATHER_DATA_SOURCE_AUDIT_2026-06-15.md`.
The smoke tests showed working GRIB subsets from NOMADS HRRR, NBM, and RTMA,
and live ECCC HRDPS GRIB2 files on MSC Datamart. MRMS precip products are
available as gzipped GRIB2 objects on public S3.

Why this is missing: the current adapters are mostly JSON/CSV/XML. HRRR, NBM,
RTMA/URMA, MRMS, and HRDPS need common handling for subregion requests, nearest
gridpoint extraction, file indices, compression, model run metadata, and local
cache cleanup.

## Implementation Design

Local strategy:

- Prefer `wgrib2` for nearest-gridpoint extraction when it is installed or
  configured by path. It is a small CLI dependency and avoids pulling a large
  GDAL/ecCodes stack into the project by default.
- Keep the default path dependency-light: fetch/probe/metadata helpers only
  need `requests` and the standard library. If `wgrib2` is unavailable, nearest
  extraction fails with an explicit `GribToolUnavailable` error instead of
  silently returning fabricated values.
- Do not add `cfgrib`, `pygrib`, GDAL, or ecCodes as mandatory dependencies in
  this slice. The current Windows environment has none of those installed.

Module design:

- Add `weather.sources.grib_probe` with schema `grib_probe_v0.1`.
- Core functions:
  - `is_grib2(payload)` validates GRIB magic and edition.
  - `parse_idx_lines(text)` parses NCEP-style `.idx` lines into message number,
    byte offset, variable, level, forecast step, and raw line.
  - `select_idx_records(...)` filters parsed index records by variable and
    level text.
  - `build_nomads_subset_params(...)` creates source-neutral NOMADS subregion
    request parameters for variables, levels, file, directory, and bounding box.
  - `probe_grib_payload(...)` emits provenance metadata with payload hash,
    payload size, optional object key, source URL, run/forecast metadata, and
    parsed index records without parsing all GRIB fields.
  - `extract_nearest_with_wgrib2(...)` wraps `wgrib2 -match ... -lon lon lat`
    and parses scalar values from CLI output.
  - `normalize_grib_row(...)` emits source-schema-compatible rows with source,
    model, field, run time, forecast hour, valid time, unit, grid/domain, source
    URL, payload hash, and fetch time.
- Rate/cache policy is represented as a small `GribCachePolicy` dataclass with
  max age, max bytes, and provider pause seconds. Cleanup and provider-specific
  scheduling can build on this without hard-coding source behavior.

Verification:

- Use generated byte fixtures for GRIB2 magic validation.
- Use tiny checked-in strings for `.idx` parsing and NOMADS parameter building.
- Use a fake `wgrib2` runner for nearest-point extraction parsing so tests do
  not require local GRIB tooling.
- Keep live probes optional and skipped by default.

Out of scope for this implementation slice:

- Downloading and parsing full live HRRR/NBM/RTMA/MRMS/HRDPS products in tests.
- Installing or vendoring `wgrib2`, GDAL, ecCodes, `cfgrib`, or `pygrib`.
- Provider-specific adapters; items 79 and 80 will build on the neutral helper.
