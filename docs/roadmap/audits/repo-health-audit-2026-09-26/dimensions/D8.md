## Proposed ratchets

1. **Venv-drift check** (F1). Add `python -m weather.operations.dependency_drift` (stdlib `importlib.metadata`), which compares
   every exact pin in requirements.txt (plus the `test` extra) with installed versions and exits non-zero on mismatch or
   absence. Wire it into `status.ps1` as a WARN line, and into `quiet_window_merge.ps1` as a post-merge step: if the merge
   changed requirements.txt/pyproject.toml, report the drift and require an explicit venv sync before the capture-recovery
   proof. The bounded suite records it in its receipt.
2. **Undeclared-import ratchet**. A test that AST-scans `src/` and `app/` for top-level third-party roots and requires each
   one to be declared in pyproject (dependencies or a named extra), with a small reviewed allowlist for transitive packages
   (initially joblib, eth_account). This would have caught pyarrow.
3. **Workflow ratchet**. A test over `.github/workflows/*.yml` that asserts: no `lfs: true`, no `secrets.`, no
   `pull_request_target`, `permissions: contents: read`, and every test path named in a workflow exists. It could also
   require every workflow to be named in `docs/development.md`, which catches F5.
4. **Branch lifecycle rule** (for git-workflow.md). A codex/* topic branch that is an ancestor of origin/master is listed in
   the next recorded-retirement manifest by the production agent within 7 days of landing, and deleted remotely by the same
   one-shot push task that publishes master. Unmerged branches older than 14 days with no open PR and no canon mention get an
   `archive/<name>` tag, **pushed and verified with ls-remote**, before deletion. `deployed/*` tags are written for every
   executed one-shot source. `preserve/*` and held branches are never auto-retired.
5. **Tag push check**. `status.ps1` compares local `archive/*`/`deployed/*` tags against `git ls-remote --tags origin`
   (at most once per day) and warns on local-only tags.
