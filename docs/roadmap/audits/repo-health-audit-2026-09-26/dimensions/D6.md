## Skeptic pass

- **S1 (D6-01).** *For leaving it:* the pin is the feature, and the deployed worktree is the reviewed source, so master
  divergence is harmless. *Refutation:* the harm is in the other direction. Master's registrar is the only one in the repo,
  `scripts/ops/AGENTS.md:3-5` calls it the source of truth, and OPERATIONS_DESIGN:109 has to warn people not to use it.
  Master's watchdog also contains fixes (09-24 `e14219b54`) that the deployed copy lacks. The row survives: land the pinned
  registrar on master, and re-deploy under owner-ops review.
- **S2 (D6-02).** *For leaving it:* PowerShell is the only thing on the host that can read Scheduler and CIM state without
  Python cold starts, and moving the logic adds a Python dependency to the monitor. *Refutation, partial:* status already
  shells to Python 3 times per pass. The proposal moves only the pure classifiers, which take JSON in and return a verdict
  out; gathering stays in PS. The publication-state block is action-bearing (it gates a credential-bearing push hint), so it
  moves last, with parity tests. Downgraded for that block: document now, refactor after the incident mode is formally
  retired (`scripts/ops/AGENTS.md` "spent one-time incident mode").
- **S3 (D6-05).** *For leaving it:* `register_clob_enrichment.ps1 -Unregister` exists, so the script is also the
  disarm tool. *Refutation:* the guard (`-AcknowledgeRetired`) blocks only the register path, and the unregister path stays.
  Separately, `WeatherClobEnrichmentLoop` should be added to status's expected-state handling, or it should be documented
  that the task is unregistered and not merely Disabled (UNVERIFIED which). The row survives.
- **S4 (D6-06).** *For leaving it:* each binder deliberately re-states the expected action so that an attacker who edits one
  shared definition cannot widen all three. *Refutation, partial:* a single tracked XML with a sha256 checked by all three is
  at least as strict, and it removes silent drift between binders. However, `production_baseline_scheduler_rpc.ps1` serves the
  spent incident mode. Downgraded: consolidate `quiet_window_merge` and `reconcile_integration_attempt` only, and leave the
  incident RPC frozen. Owner decision.
- **S5 (D6-11).** *For keeping it in place:* OVERNIGHT_BRIEFINGS:245 and handoff 69a describe `WeatherExecTapePilot`, and a
  reader tracing that evidence expects to find the script under `scripts/ops/`. *Checks:* (a) no static import (script, not
  module; basename 0 hits); (b) no basename or `-m` mention in scripts, docs/operations, README, .github or .codex; (c) no
  string-built import possible (`scripts/ops` is not a package); (d) no registrar, since the one-shot was host-local and is
  spent; (e) `b42839cfb` 2026-08-09 "stage one is a pilot, not a producer"; (f) not a src module. EF:2410 cites the 08-14
  bounded probe, not this file. *Refutation:* archive keeps it in git, and adding one line to the 08-10 report's companion
  doc preserves the trace. The row survives as **archive**, not delete.
- **S6 (D6-12).** *Against archiving:* check (d) cannot be proved without the Scheduler, and a host task could call it by
  path. Checks (a)-(c) and (e) passed (0 hits; commit "add", 06-18). Downgraded to owner-decision until someone confirms there
  is no host task.
- **S7 (D6-13).** *Against consolidating:* each wrapper has lane-specific refusals (the archive lane refuses 04:45-06:45,
  `production_cold_archive_run.ps1:50-51`; night segments), per-wrapper tests, and in some cases hash-pinned actions. One
  shared helper turns a single bug into seven broken lanes. *Result:* downgraded to **document**. Extract only the window
  check (ps-ops-8 already recommends that) and the kill-on-close launch, which is already shared through
  `windows_kill_on_close_job.ps1`.

## Proposed ratchets

1. **Whole-tree PS AST ratchet.** Replace `PARSE_SCRIPTS` with `scripts/ops/**/*.ps1`. The check fails on parse errors, on an
   operator-named `CommandParameterAst`, on assignment to read-only automatics (this exists for `$PID`: `test_memory_commit_guard_script.py:159`),
   and on a `BinaryExpressionAst` of `+` whose right operand is a `-f` format expression. Add the test to
   `windows-qualification.yml`.
2. **Task-inventory ratchet.** Add a tracked `config/scheduled_tasks.json` listing each name with its registrar (or
   `host_local_xml` and its sha256), state (`armed`/`disabled`/`retired`/`one_shot_spent`) and owning doc. A Linux test then
   checks that (a) every `TaskName` literal in `scripts/ops` and every name in `status.ps1` `$expDisabled`/`$expNonZero` is in
   the inventory; (b) each `retired`/`disabled` entry's registrar refuses without `-AcknowledgeRetired` (D2 ratchet 3);
   (c) each `armed` name appears in OPERATIONS_DESIGN.md; (d) `status.ps1`'s expected-disabled set equals the inventory's
   disabled and retired set; (e) `OPERATING_REFERENCE.md` renders the table from it.
3. **Cross-script string-contract test.** Build the status flag format once and assert that `health_watchdog.ps1`'s
   classifier regexes match it (this closes the ps-ops-3 class).
