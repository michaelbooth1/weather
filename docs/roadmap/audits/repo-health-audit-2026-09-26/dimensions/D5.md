**What a physical move would break.** Measured, not assumed:
1. `correspondence_index.correspondence_rows` globs `docs/roadmap/*.md` without recursion, and `git_added_dates` restricts its
   history to `docs/roadmap/workstation-handoff-*.md` and the similar patterns, with `--no-renames`. A file moved to
   `archive/<yyyy-mm>/` **would silently drop out of the index** (no error). If the patterns were widened, the move commit would
   become its "added" date and the chronology would be falsified.
2. `agent_docs_audit._is_immutable_record` requires `path.parent.name == "roadmap"`. Moved records lose their immutability
   exemption, so every stale outbound link in them turns the audit red.
3. The flat Markdown files carry **2,347 relative outbound links** (`../`, `items/`, `audits/`, sibling `.md`). A move one
   level deeper breaks all of them. Repairing them means editing records that `docs/roadmap/AGENTS.md` declares immutable.
4. Inbound: 68 backticked or linked citations of correspondence basenames from operations, items, audits and research. The
   established findings cite by path (`docs/roadmap/agent-report-…md`), so those would go stale too.

## Archive proposal (answering "propose one")

**Recommended: leave everything in place and exclude it from agent routing (already done), plus generated reachability.**

1. Shard the correspondence index by Git-added month (D5-1). Closed months become stable files, which ends the per-branch
   conflict hotspot.
2. Extend the generator, or add a sibling module, to emit `docs/roadmap/dated-narratives-index.md`. It would cover flat dated
   `.md` files that are not correspondence (audits, pre-registrations, plans, master-agent handoffs), so the 10 orphans (D5-2)
   become reachable. Add parity to `knowledge_structure_audit.generated_index_errors` in the same way.
3. Entry criterion for "historical" (no move, a column in the index): the file is 30 days or more past its Git-added date,
   **and** no `items/`, digest, established-findings, retracted-claims, audit or `docs/operations` file cites its basename or
   mission id. The generator can compute this with the same token scan as `d5_refs2.py`, which runs in about 2.5 s. The index
   marks the row `historical`, and agent routing already says not to open such files unprompted.
4. The physical `archive/<yyyy-mm>/` tier is **rejected for existing files** (D5-4 evidence: 2,347 broken outbound links in
   immutable records, silent index drop, immutability-exemption loss). It is an owner option only for new files after a cut-over
   date, with the generator (`rglob` + basename-keyed dates) and `agent_docs_audit._is_immutable_record` (ancestor `roadmap`)
   changed in the same commit.
5. `docs/operations/` keeps its existing tier. Dated incident records stay routed under "Dated records (historical)", and
   `history/` holds text extracted from always-loaded files. No change is needed.

## Proposed ratchets

1. **Generated-file churn guard:** a docs-audit warning when a tracked generated index exceeds N KB (for example 100 KB) or
   when a single file drives more than X% of master commits over 7 days. This would have flagged the 256 KB, 30-commit index.
2. **Reachability ratchet:** every flat dated `docs/roadmap/*.md` must appear in a generated index (the correspondence index
   or the dated-narratives index). This mirrors `unindexed_operations_docs`, and the count of unreachable files may only fall
   (10 today).
3. **Dormant-item ratchet:** `roadmap_backlog` flags an OPEN or PARTIAL item whose last disposition date is more than 45 days
   old, and requires a dated disposition refresh or a DORMANT marker. It reports this in `active-backlog.md` rather than
   failing.
4. **Superseded-owner check:** when a `docs/operations` file's header or index row says "Owns: … next …" and STATE_OF_PLAY
   links it as "history", the docs audit warns. A cheap version is a `SUPERSEDED_BY` front-line convention checked against the
   operations README row.
