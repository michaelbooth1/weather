## Method (what was actually checked)

1. **Static imports (2.2a):** a text-only AST pass over all 1,061 tracked .py files (`tmp/d1_scan.py`, no project module imported).
   It resolves `import`, `from x import y` (including submodule-as-name) and relative imports to the tracked module set.
2. **String-built / dynamic names (2.2c):** every string constant in every .py was scanned for `weather.*|maker_core.*|app.*|tools.*`
   dotted tokens. `git grep` for `import_module|__import__|runpy|run_module` found no f-string or concatenated module builders in
   src/app/tools/scripts. The only dynamic loaders are `operating_reference.py:150` and `loop_jsonl_repair.py:40`, which both load literal
   dotted strings (so the string scan covers them), plus `runpy.run_module` in `.ps1` (also literal). The two schema-registry data files
   (`schema_registry_data.py` 224 hits, `schema_registry_recent_data.py` 90 hits) hold owner strings, not callers, so they were excluded
   as evidence of use.
3. **Ops mentions (2.2b/d):** dotted names, `src/...py` paths and `basename.py` were scanned in every tracked non-.py text file.
   Leaf-name `git grep -w -F -f` covered scripts/, docs/operations, README.md, .github, .codex, config and app. The 20 `register_*.ps1`
   files are under scripts/ and were covered by these greps. `Get-ScheduledTask` was not run (forbidden).
4. **Citations (rule 2.1):** leaf names were grepped against ESTABLISHED_FINDINGS, FINDINGS_DIGEST, RETRACTED_AND_FALSE_LEADS,
   docs/roadmap/items and docs/roadmap/audits.
5. **git log -1 (2.2e):** read for every candidate. Most read `2026-06-25 add` / `2026-06-18 add`, which are bulk re-layout commits, so
   they do not show real last-use dates.
6. **Supervisor closure (2.2f):** by construction, no candidate has any non-test importer, so none can be in a supervisor import closure.
   `roll_verdict.ps1` was not run.
7. **Off-master branches:** the candidate leaf names were grepped on `origin/codex/integration-91a-110f-20260926`,
   `maker-replay-harness-20260926` and `weather-maker-plugin-20260925`. The only new hit is a *stage name*
   (`afternoon_residual_centering`) in `maker_plugin/fair_value.py:134,162`. No branch imports a candidate module.
8. **Entry points:** there are 305 modules with `if __name__ == "__main__"`, and 83 distinct `-m` targets in scripts/docs/operations/
   README/.github/.codex/config (one of them, `weather..`, is a malformed doc token).

## Skeptic pass (rule 2.3)

- **S-01 (runtime_identity facade).** Opposing case: a scheduled .ps1 or an external workstation script might run
  `-m weather.operations.runtime_identity`. Refutation: the `-m` census has no such target, and the ops `runtime_identity` hits are JSON
  keys (`quiet_window_merge.ps1:1954,1970,3572`; `roll_verdict.ps1:124`; `staleness_sweep.ps1:166`). The facade has no `__main__`.
  Opposing case 2: pickles. Refutation: `import *` does not change `__module__`, so pickles bind `weather.runtime_identity`.
  **Survives, high.**
- **S-02 (fix_app/train_all/train_all2).** Opposing case: README or a runbook still says to run `train_all.py`. Refutation: the grep of docs/,
  README.md and scripts finds only item-330:673, which prescribes deletion, and full-audit architecture.md:284. README:400 names
  `tools\train_all_markets.ps1`, a different file, which stays. `test_research_harness.py:15-16` requires inventory and files to match,
  so the rows must be deleted together with the files. **Survives.**
- **S-03 (13 uncited tombstones).** Opposing case: `test_retired_scripts_expose_help…` (`test_research_harness.py:35-54`) would lose
  coverage. Refutation: it iterates the inventory; with fewer rows it still passes. `test_broken_research_fragments_stay_retired` names
  only nyc and chicago, which are excluded (D1-04). **Survives.**
- **S-05 (June one-offs).** Opposing case: `summary.py` has 15 doc hits. Refutation: those are other files called `summary.py`; the
  path-exact scan finds 0 mentions of `tools/research/summary.py`. Opposing case 2: decompose_1314 is the smoke fixture
  (`test_research_harness.py:31`). This is a real dependency, so the row is **downgraded to archive** with a fixture swap, not delete.
- **S-06 (reporting/research).** Opposing case: items 134-224 cite these modules as the reproducible producer of their dispositions.
  Deleting them breaks "restore compatible code from a retained commit" only weakly, because git keeps it. Still, rule 2.1 applies.
  Opposing case 2: the schema registry would fail `test_schema_registry` if the owner strings no longer resolve. Refutation: none;
  this is real. **Downgraded to archive** (move under an excluded archive tree together with tests and registry rows). Quiet-window
  because `schema_registry_data.py` is in the supervisor closure (`src/weather/schema_registry.py:14`, imported by
  `operations/supervisor.py` and `operations/observation_trigger.py`).
- **S-07 (validation).** Opposing case: `point_in_time_evaluation.py`, the 5,494-line live validation, imports helpers from these.
  Refutation: the AST importer map shows no non-test importer for any of the 10 listed modules, and point_in_time_evaluation is not in

- **S-08 (casebooks/postmortem/registration_parameters).** Opposing case: registration_parameters was meant as the fail-closed input

## Proposed ratchets

1. **Orphan-module ratchet** (tests/operations/test_import_architecture.py). Build the AST import graph for src/app/tools and add
   literal dotted strings in src plus `-m` / runpy / path mentions in scripts, .github, .codex and docs/operations/README. Fail when a
   `src/weather` module has no non-test importer and no ops invocation, unless it appears in an explicit `KNOWN_ORPHANS` allowlist that
   may only shrink. Seed the allowlist with the 75 modules above. Exempt schema-registry owner strings as evidence of use.
2. **No tombstones in research_harness.** Forbid `status: "retired"` rows in `SCRIPT_INVENTORY` (git history is the tombstone). Require
   each new tools/research script to carry an item/mission id in its name or notes.
3. **Producer-consumer check.** For every `backtest_path(..., "<name>.json")` read in daily_refresh/promotion/scoreboard code, assert that a
   daily_refresh step, scheduled task or documented runbook produces `<name>.json`. This would have caught D1-09.
