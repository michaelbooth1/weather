## Skeptic pass

- **S1 (D2-01).** *Against:* the taker evidence feeds daily learning, so skipping loses information. There is also an
  "EF-cited" countability lane. *Refutation:* the taker has been paused since 08-07 and retired, with its tasks Disabled
  (`status.ps1:3644-3656`). No new taker runs exist, so the daily outputs are recomputations of frozen data. The
  `taker_edge_permission_map.json` consumers are only the retired taker (`taker_bot_sizing.py:299`,
  `taker_bot_strategy_registry.py:216`). *Against 2:* SKIPPED on a critical dependency is a blocker. *Refutation:*
  `daily_refresh_settled_day.py:190-191` turns SKIPPED into non-critical when `skippable_as_non_critical` is True, and all
  three taker rows set it (`:39-55`). *Residual risk:* `daily_learning_scorecard.py:1589-1590` and `daily_flow_analysis.py:47`
  read the stale JSON. They would then show the last-written artifact, not a fresh one (not verified whether they flag age).
  The row survives.
- **S2 (D2-02).** *Against:* the owner may resume the paper maker, and the alert is how the operator learns it died.
  *Refutation:* make the check honour the same paused flag or registry and keep it switchable. That keeps the alert for
  resumption while ending the daily false critical. The row survives as a refactor. Whether the host already suppresses the
  alert is not verified.
- **S3 (D2-03).** *Against:* a guard adds friction to a legitimate resume. *Refutation:* a `-AcknowledgeRetired` switch is
  one flag, and `status.ps1:3656` already requires a deliberate re-enable. The row survives.
- **S4 (D2-04).** *Against:* `mm_policy.utc_now` could differ subtly from `weather.time.utc_now` (tz or format), and live
  receipts may hash its output. *Refutation:* not checked line by line. Downgraded: copy the helpers verbatim into a neutral
  module and re-export them from `mm_policy`; do not substitute `weather.time`. Confidence for "behaviour identical" is med
  until the diff is reviewed.
- **S5 (D2-05).** *Against:* AGENTS.md explicitly keeps Polymarket US code as a compatibility surface, so deleting it
  violates the contract. *Refutation accepted:* downgraded from delete to "refuse mutation", owner-decision.
- D2-06, D2-07 and D2-10 propose no delete or archive, so they are reported as `document` at most, per rule 2.3.

## Proposed ratchets

1. **Capture-closure retired-import ratchet.** Add a test in `test_import_architecture` using the same static AST closure:
   no module matching `taker_*|mm_paper*|market_making_run*|mm_policy` may enter the closure of the five capture supervisors
   or of `maker_core`.
2. **Retired-component registry.** A config file listing retired steps, tasks and modules, plus a test that checks:
   (a) `daily_refresh_contract.ps1` passes a skip or paused flag for every retired step;
   (b) `status.ps1` `$expDisabled` lists every retired task;
   (c) `nightly_health_checks` does not emit critical alerts for retired components;
   (d) the count of importers of retired modules from outside their family is pinned to an allowlist and cannot grow.
3. **Register-script guard.** Test that every `register_*.ps1` for a registry-retired task refuses without
   `-AcknowledgeRetired`.
4. **`_c` identifier ratchet.** The set of distinct `\b[a-z_]+_c\b` identifiers in `src/` (85 today) cannot grow without an
   allowlist entry stating "true Celsius", "native (legacy)" or "not a unit". New code uses `_native` or an explicit `_celsius`.
