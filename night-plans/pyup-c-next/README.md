## Night timeline (host local, America/Toronto, EDT; not a DST night)

1. **Before 00:30.** Put the prerequisites in place (`aux-tasks.txt`, `q12.txt`, `gap-overrun.txt`, and `q12b.txt`

2. **00:30:00. Run the standalone C0** with `-G3Mode` and the G3 values (see "G3" below). C0 refuses before 00:30
   and refuses without a valid `-G3Mode`. It prints `G3 PASS mode=<m> branch=...` or `G3 FAIL reason=...` and, only
   on PASS, writes the flag. Line 2 of the flag records the mode and the G3 operator values.
3. **GO review.** Master reviews the C0 receipts and the G3 PASS line, then writes `owner-go-20261024.txt` with
   first token `GO`.
4. **About 00:32 or later. Launch the retry wrapper.** Each attempt re-runs C0, including G3, from the flag's
   values, then runs C1, which takes the lease. The C1 window is **00:30 to 01:04**.
5. A pass case ends at about 01:40-01:50 when the lease is taken around 00:31.

**G3 in this timeline.** G3 runs inside C0: once in the standalone C0 at about 00:30, and again in every attempt's
C0 re-run. Each attempt runs it before C1 takes the lease and before C2 touches anything. A G3 fail therefore
comes before C3 and costs no capture gap. It is deterministic, so it is never retried:

- the standalone C0 writes no flag, so the attempt's preflight refuses with exit 3 and
  `PYUPC-GATE-REFUSAL gate=PREFLIGHT`;
- inside an attempt, the run file logs `G3 FAIL`, NO-GOes and prints `PYUPC-GATE-REFUSAL gate=G3`.

Either way the wrapper's verdict is `STOPPED reason=GATE_REFUSAL_*`.

### How the kit implements it

`Test-G3Gate` is identical in both files: run file :309-337, C0 file :157-185. All git is read-only.

- **The mode.** `-G3Mode` is mandatory, case-sensitive and has no default.
  - C0 refuses (exit 3) before anything else unless it is exactly `strict` or `dependency`.
  - `Test-G3Gate` also fails with `g3mode_missing_or_invalid`.
  - C0 records the mode on the flag line: `G3 mode=<m> branch=... tip=... pregate=... tested=... py=...`. Every
    attempt re-checks G3 with that recorded mode.
- **Operator values.** The other values are fixed for 10-23/24 by master's ruling, are not hardcoded in any
  `.ps1`, and are already filled in the two launch lines below.
  - `-G3QualifiedTip 90b2e1844ad0de71916c67996026dea7b04ce5ff`: must equal `qualification.json` `tip`, else
    `G3 FAIL reason=operator_tip_ne_qualification_json`.
  - `-G3PregateReceipt pg-739c03eff1e2-20261018T045220-105120`: a PASS receipt. It is not on the host, so the kit
    records only the id.
  - `-G3TestedSha 739c03eff1e2f26c49759899e4e39b669d2c6628`: must be 40-hex, start with the receipt's 12-hex head,
    and exist in the production repo.
  - `-G3PregatePython 3.11.9`: an attestation. The workstation venv is 3.11.9, and the pregate uses
    `$RepoRootenv` (`workstation_pregate.ps1:60`).
- **Both modes: HEAD equals the tip.** PASS, branch `HEAD==tip`.
- **strict, HEAD ≠ tip:** `G3 FAIL reason=STRICT_HEAD_NE_TIP`.
  - It is preceded by the pre-ruling kit line, verbatim from 353167c0e:251: "HEAD moved from the qualified tip; G3
    needs roll_verdict.ps1 -Branch <HEAD> -Base <tip> exit 0 (ROLL-FREE) attached before GO, else B-R".
  - Unlike 353167c0e, strict mode then NO-GOes, as the amendment requires. A ROLL-FREE verdict can no longer carry
    the night inside the kit: it is master's or the owner's call (B-R, or `dependency` mode).
- **dependency, HEAD ≠ tip:**
  - **(i):** `git diff --name-only <tip> HEAD`. A path fails when its leaf name matches `requirements*`,
    `constraints*`, `*.lock`, `pyproject.toml`, `setup.cfg` or `setup.py`, at any depth.
  - **(ii):** `git diff --name-only <tested sha> HEAD`. Every path must match `^docs/.+\.md$` or be exactly
    `config/locations.json` or `config/location_market_events.json`. The match is exact and case-sensitive, with
    no globbing. Any other path fails with `nondocs_diff=<n>:<paths>`.
  - **(iii):** the PASS line is printed only after every other C0 check has passed.
- **Fixed output.**
  - `G3 PASS mode=<m> branch=HEAD==tip tip=<sha>`
  - `G3 PASS mode=dependency branch=(i)+(ii)+(iii) deps_changed=none pregate=<id> tested=<sha> nondocs_diff=empty fleet_drift_exempt=<paths in git order|none>`
  - `G3 FAIL reason=<token> mode=<m> head=<sha> tip=<sha>`, followed by `NO-GO: G3 FAIL: ...`
- **On a fail:** no retry. The wrapper sees `GATE_REFUSAL_PREFLIGHT` from the standalone C0, or `GATE_REFUSAL_G3`
  inside an attempt. Then B-R per the ruling, and a new C0.
- **Operator command:** the owner's D1 answer picks exactly one of these two lines.
  - dependency: `Start-Process powershell.exe -Verb RunAs -ArgumentList '-NoProfile -ExecutionPolicy Bypass -File C:\pyup\cp3119\phase-c0-run-20261024.ps1 -G3Mode dependency -G3QualifiedTip 90b2e1844ad0de71916c67996026dea7b04ce5ff -G3PregateReceipt pg-739c03eff1e2-20261018T045220-105120 -G3TestedSha 739c03eff1e2f26c49759899e4e39b669d2c6628 -G3PregatePython 3.11.9'`
  - strict: `Start-Process powershell.exe -Verb RunAs -ArgumentList '-NoProfile -ExecutionPolicy Bypass -File C:\pyup\cp3119\phase-c0-run-20261024.ps1 -G3Mode strict -G3QualifiedTip 90b2e1844ad0de71916c67996026dea7b04ce5ff -G3PregateReceipt pg-739c03eff1e2-20261018T045220-105120 -G3TestedSha 739c03eff1e2f26c49759899e4e39b669d2c6628 -G3PregatePython 3.11.9'`

- The only floor for a lease user is minute 30 (`workload_admission.ps1:596-598`).

- `rev-parse HEAD` (run :263, :341);

- the G3 `diff --name-only` and `cat-file -t` calls (run :317, :324-325, and the same in C0).

`git status` can briefly take `.git\index.lock` to refresh the index.

Collision analysis:

- From C1 to the release, C holds the lease, so any QWM run fails at `:3284` before touching git.
- Before C1, the C0 re-run (≈13 s) and the standalone C0 run without the lease.
- A ROLL-FREE QWM is admitted from 00:30, so on this night the 00:30-01:00 slot is no longer free of possible
  merges. A merge running at that moment would make C0 NO-GO ("prod tree dirty", or HEAD differing from the flag
  gives exit 4). Both are deterministic gate refusals with no retry. C0's `git status` could also make that merge
  fail on `index.lock`.
- G5 (no merge or integration attempt that night) and the C0 next-runs check (any non-exempt task due before
  04:00 must be absent from the GO review) are the guards.

## Retry markers and decision

The marker formats and the decision table live in the run file and wrapper headers. The self-test (a scratch
script, not in the kit) dot-sources the wrapper and feeds it fake transcripts. It passes 20 decision cases, 14 G3 cases (4 of them in a throwaway git repo for fleet drift)
and 1 static check that `-G3Mode` has no default.

Retries happen only for a stop before C3 that:

- exits 1,
- carries `PYUPC-RESTORE-VERIFY result=PASS`,
- carries no `PYUPC-GATE-REFUSAL` marker, and
- leaves the next start at or before 01:04 and before 03:30, within 3 attempts.

Anything at or after C3, or any marker that is missing or unparseable, gives WAIT-FOR-OWNER.
